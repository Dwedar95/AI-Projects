# genai-usecase-governance-toolkit

A Python toolkit and CLI for the analytical part of GenAI discovery and governance work:
use-case portfolio prioritisation, business cases, an EU AI Act oriented risk triage,
Responsible AI evaluation and Markdown report generation.

## What it is

`genai-gov` takes a use-case portfolio described in YAML and a tabular prediction file and produces:

1. A ranked portfolio from configurable weighted multi-criteria scoring (value, feasibility, risk),
   a sensitivity analysis of that ranking to the weights, and a build / buy / partner recommendation.
2. A business case per use case: build, run, token / inference and change management cost against
   benefit cash flows, with NPV, ROI, payback, IRR, a tornado table and a seeded Monte Carlo simulation.
3. An indicative risk tier per use case (prohibited, high-risk, limited, minimal) from a rule-based
   questionnaire oriented on Regulation (EU) 2024/1689, with the reasons and an obligations checklist.
4. Performance metrics and group fairness metrics (demographic parity difference, equalised odds
   difference, disparate impact) for a prediction CSV, and a system card in Markdown.
5. Markdown reports: a roadmap with delivery waves, a risk register and a RACI matrix.

Everything runs offline on CPU. No LLM or cloud service is called.

## Background

Reference implementation by the author of the working method it encodes: M. Emad Dwedar, AI researcher at
TUM Heilbronn, co-founder of AsetraAI, Microsoft AI Consultant and Azure Solutions Architect Expert.
The toolkit reflects how the author structures AI discovery and governance engagements: score the
portfolio in a workshop, test how fragile the ranking is, put numbers on the top candidates, screen
regulatory exposure early and hand over a roadmap with owners.

This is an independent open-source project. It is not a Microsoft tool, it is not the code of any
client engagement, and all example data in `examples/` is fictional or synthetic.

## Important disclaimer on the risk triage

The risk triage is a simplified screening aid. It encodes a subset of the EU AI Act as yes/no questions,
does not model every exception, does not encode application dates and can be wrong. It is not legal
advice. Every result must be confirmed by qualified legal counsel. The same disclaimer is printed by
the CLI and written into every generated report.

## Features

| Area | Module | What it computes |
|---|---|---|
| Prioritisation | `scoring.py` | Weighted criteria per dimension, 0 to 100 overall score with risk inverted, quadrant label |
| Sensitivity | `scoring.py` | One-at-a-time weight shifts, Dirichlet Monte Carlo rank stability, Kendall tau, smallest shift that changes rank 1 |
| Sourcing | `scoring.py` | Build / buy / partner score from six rated factors with rationale and close-call detection |
| Business case | `roi.py` | Cash flows, NPV, ROI, interpolated payback, IRR by bisection, tornado, Monte Carlo with triangular ranges |
| Risk triage | `risk_triage.py` | 21 screening questions plus derogation and context questions, Art. 6(3) derogation logic, provider and deployer checklists, keyword pre-fill from the description |
| Responsible AI | `fairness.py` | Accuracy, precision, recall, F1, specificity, ROC AUC, Brier, per-group rates, DPD, EOD, disparate impact, bootstrap interval |
| System card | `cards.py` | Markdown card filled only from metrics that were computed |
| Reports | `reports.py` | Wave planning with capacity and dependencies, risk register (likelihood x impact), RACI per tier |

## Quickstart

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

genai-gov prioritise examples/portfolio.yaml
genai-gov sensitivity examples/portfolio.yaml
genai-gov build-buy examples/portfolio.yaml --use-case UC-04
genai-gov roi examples/portfolio.yaml --use-case UC-01
genai-gov triage examples/portfolio.yaml --use-case UC-03
genai-gov triage --describe "A chatbot that ranks loan applicants" --role deployer
genai-gov fairness examples/data/predictions_synthetic.csv
genai-gov card examples/portfolio.yaml --use-case UC-03 --predictions examples/data/predictions_synthetic.csv
genai-gov report examples/portfolio.yaml --out out
```

`make demo` runs all of the above in one script (`examples/run_demo.py`).

The suite has 55 tests. Scoring, NPV, payback, IRR, ROC AUC and the fairness metrics are checked
against hand-computed values, the triage rules against explicit cases (precedence, derogation,

## Limitations

- The risk triage covers a subset of the regulation. It does not model general-purpose AI model
  obligations, the exceptions inside Article 5, sector law, national law or application dates.
  Keyword matching on the description is a crude pre-fill, misses paraphrases and can produce false
  hits; explicit answers override it. The result is indicative and not legal advice.
- Scores are human judgements entered in YAML. The tool makes the consequences of the weights
  visible, it does not make the scores objective.
- The build / buy / partner helper is a linear factor model with coefficients chosen by the author.
  They are in one table in `scoring.py` and should be reviewed before use.
- The Monte Carlo simulation draws drivers independently from triangular distributions. Correlated
  drivers (for example adoption and benefit) are not modelled, which understates tail risk.
  Change management cost has no uncertainty range.
- Fairness metrics need binary labels and predictions and one sensitive attribute per run. No
  intersectional analysis, no significance test beyond a bootstrap interval for demographic parity.
- The risk register and RACI are generated from rules and templates. They are a starting point for
  a workshop, not a finished governance design.
- No LLM is used. Use-case descriptions are not interpreted beyond keyword matching.
